# ЛР12 — модель угроз Phonoteka v2

## Изменение относительно v1

Модель v1 в `THREAT_MODEL_LAB12.md` фиксирует только исходный commit `eadf4b0`. После hardening добавлены локальный PIN-gate, CryptoObject для сильной биометрии, step-up для деталей трека, зашифрованная внутренняя резервная копия, лимиты загрузки, Room-кэш каталога постов, debug-only TLS-клиент и ограничения release-манифеста. Внешняя Activity по-прежнему должна быть экспортирована как launcher; поэтому для Phonoteka невозможно буквально выполнить условие «только InviteActivity exported» без разрушения запуска приложения. Её Intent и deep link нужно проверять отдельно.

## Активы и контроль доступа v2

| Актив | Граница/владелец | Контроли после изменений | Остаточный риск |
|---|---|---|---|
| Музыкальная библиотека и статусы треков | App-private Room; пользователь устройства | PIN HMAC через AndroidKeyStore, свежая аутентификация перед деталями, экспорт библиотеки через SAF | PIN локальный, общий Android user может удалить приложение; защита не покрывает root |
| Внутренняя копия библиотеки | `filesDir/backups/phonoteka-library.enc` | AES-GCM и неэкспортируемый AndroidKeyStore ключ, атомарное временное имя и rename | удаление/инвалидирование Keystore-ключа делает копию невосстановимой; внешний SAF export не шифруется приложением |
| Сетевой каталог постов | JSONPlaceholder ↔ Retrofit ↔ Repository ↔ Room | HTTPS, Room как offline cache, типовые network/HTTP/parse сообщения | публичный API демонстрационный, не гарантирует доступность и целостность бизнес-данных |
| Сетевые аудиоисточники | сторонние сайты ↔ загрузчик | HTTPS, ограничение размера/сегментов, диагностические сообщения без query URL | сам NewPipeExtractor и внешние CDN остаются внешней поверхностью атаки |
| Сессия локального auth | MainActivity, SharedPreferences метаданных, AndroidKeyStore | PIN хранится только как keyed HMAC; биометрия выполняет AES/GCM через CryptoObject; одноразовый recovery | локальный демо-вход не является серверной MFA и не имеет реального сервера отзыва токена |
| Сетевой лабораторный секрет | debug-only `localhost` fixture | HMAC, timestamp, nonce, локальная replay guard, два pins | общий HMAC-ключ fixture не подходит для production; MITM runtime не доказан |
| Логи безопасности | локальные prefs | события успеха/отказа/lockout и доступа | владелец/root может изменить локальную запись; retention ограничен |

|---|---|---|---|

## План атаки, защиты и риск

Три контролируемых плана, шаги, критерии успеха, способы детекции, реакция и ALE находятся в `ATTACK_PLANS_LAB12.md`. Все описаны только для своего приложения и loopback fixture. Документ фиксирует, что это план проверки, а не уже полученное доказательство эксплуатации.
