# ЛР12 — учебные планы проверки защиты

Все сценарии ниже ограничены собственной debug-сборкой Phonoteka и локальным эмулятором/сервером. Это планы проверки, а не утверждение, что атака уже выполнялась.

## План красной команды

### RT-01 — подмена параметра deep link

- Профиль: пользователь без специальных навыков; доступ к разблокированному тестовому устройству.
- Предпосылки: debug APK установлен, в базе есть треки с известными идентификаторами.
- Шаги: открыть валидную ссылку `phonoteka://details/1`; повторить с `0`, отрицательным числом, очень длинным числом и буквенным ID; проверить экран, журнал и состояние базы. Использовать только данные тестовой библиотеки.
- Успех атаки: приложение показывает чужой/несуществующий объект либо падает/обходит step-up.
- Детекция: `adb logcat` фильтр `AndroidRuntime|ActivityTaskManager|Phonoteka`; проверить экран и состояние Room до/после.
- Стоимость/риск: 10–20 минут; низкий риск на отдельном AVD.

### RT-02 — подмена TLS и повтор запроса

- Профиль: исследователь с локальным mitmproxy; полномочия только на тестовый трафик своего приложения.
- Предпосылки: локальный HTTPS mock server, тестовый сертификат и тестовый HMAC key вне Git.
- Шаги: отправить запрос без proxy для baseline; включить proxy и тестовый CA; проверить debug-клиент; повторить запрос с тем же nonce; затем изменить тело/подпись. Не направлять proxy на чужой трафик.
- Успех атаки: недоверенный сертификат принимается, replay проходит повторно либо изменённое тело принимается серверной фикстурой.
- Детекция: TLS exception/pinning result и ответы fixture `REPLAY`/`INVALID_SIGNATURE`; сохранить локальный лог без секретов.
- Стоимость/риск: 30–60 минут; низкий риск при loopback-only стенде.

### RT-03 — злоупотребление локальным входом и резервной копией

- Профиль: человек с кратким физическим доступом к разблокированному тестовому устройству.
- Предпосылки: debug APK, пустая тестовая библиотека, PIN и recovery-код тестового профиля.
- Шаги: выполнить пять неверных PIN; убедиться в lockout; применить recovery-код один раз и повторить его; прочитать внутренний файл `.enc` без вызова приложения; проверить отказ при повреждённом GCM tag.
- Успех атаки: блокировка обходится, recovery-код повторно принимается, данные читаются из внутренней копии либо повреждение незаметно импортируется.
- Детекция: audit events, lockout timestamp, исключение GCM, число треков до/после.
- Стоимость/риск: 20–40 минут; низкий риск только на тестовых данных.

## Количественная оценка риска

ALE здесь — учебная оценка ожидаемых потерь, не финансовый факт. Для маленького локального каталога принимается условная цена часа восстановления/поддержки 1,000–2,000 ₽.

| Сценарий | Оценка годовой частоты | Потери на случай | ALE в год | Контрмера |
|---|---:|---:|---:|---|
| RT-01 некорректная внешняя ссылка | 0.2–1 | 1–3 часа | 200–6,000 ₽ | валидация и тесты, несколько часов разработки |
| RT-02 подмена/повтор debug-запроса | 0.05–0.3 | 2–6 часов | 100–3,600 ₽ | pinning/HMAC/replay guard, учебная реализация уже включена |
| RT-03 доступ к локальной библиотеке | 0.1–0.5 | 2–8 часов | 200–8,000 ₽ | локальный auth, encrypted backup, recovery и проверка устройств |

Частоты приблизительны и нужны только для сравнения сценариев. Они не являются статистикой пользователей. Из-за малой цены личной библиотеки финансовое ALE не заменяет приоритетность защиты данных и требований курса.
