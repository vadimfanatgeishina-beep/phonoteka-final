# Сетевая часть аккаунтов телефона-хоста

Подключена в main: «Настройки → Аккаунт и устройства», также доступна кнопкой из профиля. Серверные права аккаунтного API проверяются сервером. Музыкальная библиотека пока остаётся локальной с существующими локальными проверками; эти роли автоматически не заменяют DemoRoleSession.

## Состав

- `IdentityApiRouter` и 18 тестов перенесены из IdentityApiRouter.zip без изменения кода сайта. Маршруты login/refresh/logout/me/sessions/admin/password работают через PhoneIdentityAuthority. Удалённого bootstrap нет.
- `IdentityTlsServer` — ограниченный HTTPS/1.1 transport: TLS 1.2/1.3, один запрос на соединение, тело до 8 КиБ, до 32 заголовков, тайм-аут чтения/handshake, 2 рабочих потока и очередь на 4 соединения. Повторяющиеся заголовки, Transfer-Encoding, Expect, неоднозначные длины и некорректное HTTP framing отклоняются до router. Содержимое запросов/токены в лог не выводятся.
- `IdentityHostTls` — свежий самоподписанный сертификат/ключ в оперативной памяти при каждом запуске. Слушает только выбранный частный IPv4-адрес, без plaintext-порта. Сертификат живёт сутки; после перезапуска нужно повторное сопряжение. Используется okhttp-tls 4.12.0 в main, без MockWebServer в production.
- `IdentityTlsEndpoint.client()` — точная проверка публичного отпечатка сертификата и его срока, привязка к одному HTTPS origin, отключённые перенаправления и сетевые автоматические повторы. Отпечаток из будущего QR должен поступать с доверенного экрана собственного телефона-хоста. Сам отпечаток не даёт роли или входа.
- `AndroidIdentityHost` — владеет зашифрованным store и TLS transport. Открытие/создание владельца/запуск/остановка требуют переданной проверки локального владельца. Сервер нельзя запустить до создания владельца. Закрытие транспортных потоков предшествует освобождению блокировки store. Вызывать на IO.
- `PhoneIdentityClient` — клиент нового API. Вход, пользователь, собственные сессии, отзыв, создание пользователей и смена ролей администратором, смена пароля и выход. Каждая операция обращается к серверу; истёкший access обновляется однократно. При неоднозначном сбое ротации refresh не отправляется повторно автоматически. Токены только в памяти, без записи в профиль/логи. `close()` освобождает локальный клиент, для серверного отзыва вызывать `logout()`.

Старый `security/RemoteIdentityClient` относится к прежнему desktop-прототипу с другим logout-контрактом. Для нового экрана использовать PhoneIdentityClient, не смешивать протоколы.

## Проверено

Обе debug-сборки и Android test APK собираются. На JVM настоящим JUnit4 прошли 18 тестов router и 4 сетевых теста: реальный HTTPS-вход и серверные роли/выход; отказ неоднозначного HTTP framing/размера; отказ недоверенного TLS-сертификата; обновление истёкшего access с новой серверной сессией через PhoneIdentityClient.

На emulator-5556 прошёл IdentityHostDeviceTest: Android Keystore/store + локальное создание владельца + отказ запуска без владельца/локального gate + TLS + router + клиент. Включены вход, неверный pin, серверное создание сотрудника и запрет сотруднику создавать администратора, выход, повторное открытие store/сервера и чтение сохранившейся сессии. Все данные и ключи тестовые и изолированы. Два физических телефона ещё не проверены.

## Интерфейс и локальная блокировка

PhoneAccountsController живёт в Application, выполняет действия последовательно на IO и публикует StateFlow без паролей/токенов. Присоединение/выход меняет principalChanges и закрывает связанные WSS. При утрате локальной аутентификации UI-состояние очищается сразу, транспорт и клиент закрываются после текущего IO. Каждому запросу на сервер дополнительно предшествует проверка локального владельца: заблокированный хост отвечает 503 без выполнения действия.

Управление требует действительного локального входа по PIN/биометрии. Временная сессия QR2 не принимается как подтверждение владельца сервера. События core направляются в общий журнал без секретов; серверные login/logout имеют соответствующие типы событий.

Создание владельца доступно только при первоначально пустой базе и только локально. Экран автоматически выбирает частный LAN IPv4. QR сопряжения содержит только адрес/порт/публичный pin и срок 5 минут; клиент читает его встроенной камерой. Истёкшие, дублированные и публичные адреса отклоняются. «Войти на этом телефоне» позволяет владельцу подключиться к собственному серверу без сканирования.

Клиент показывает подтверждённую сервером роль и собственные активные сессии с названием устройства и временем. Есть отзыв сессии, выход и создание пользователей администратором. Отзыв текущей сессии использует logout семейства и сохраняет смысл после автоматической ротации access/refresh. Профиль показывает подключённый серверный аккаунт отдельно от местного доступа. Поле «роль о себе» не влияет на серверные права.

Дополнительные проверки на emulator-5556: PhoneAccountScreenDeviceTest прошёл создание владельца → запуск → QR → вход → список сессий → отзыв текущей → повторный вход → выход → закрытие транспорта. Отдельная проверка QR прошла. IdentityHostDeviceTest подтвердил отказ 503, пока локальный gate закрыт, и возобновление запросов после восстановления gate. UI-тест использовал изолированный store и тестовый gate; полный маршрут реального PIN/биометрии в MainActivity им не проверялся. Обе debug-сборки, lint обоих вариантов и 34 целевых JVM-теста identity прошли после интеграции.

## Осталось

Два физических телефона, реальная камера QR, смена LAN и потеря сети ещё не проверены. При смене сети требуется остановить/запустить сервер и повторить сопряжение. Хост нужно оставлять открытым; foreground-service для аккаунтного сервера не добавлен. Нет синхронизации профиля/библиотеки, истории истёкших сессий, геолокации и списка всех пользователей для админского редактирования. Клиентские методы смены роли и пароля пока не выведены в UI. Музыкальные данные и глобальная модель локальных/серверных прав требуют отдельной работы. Последние изменения main ещё не опубликованы новым подписанным релизом.
