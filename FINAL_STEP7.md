## Почему это нельзя обойти из UI
- Разрешение выдаётся только при доказательстве из криптографии: `doFinal` на шифре из `CryptoObject`. Ключ без свежей биометрии такую операцию не выполнит. Простой колбэк `onAuthenticationSucceeded` без шифра разрешения не даёт.
- Разрешение одноразовое: любая попытка `consume`, даже неудачная, его сжигает. Разрешение на чтение не открывает экспорт.
- Смена локальной сессии (повторный вход или блокировка) делает выданное разрешение недействительным.
- Цепочка проверок по порядку: свежий вход → роль ADMIN → биометрия → риск-проверка → `withVerifiedGrant` → запись в журнал с HMAC.

## Проверка на устройстве
1. ADMIN, свежий PIN → «Открыть журнал» → отменить запрос биометрии: журнал не показан, в журнале запись `audit.read.biometric` DENIED.
2. Подтвердить отпечатком: журнал показан. Нажать ещё раз: снова запрашивается биометрия.
3. Экспорт: выбрать файл, подождать больше 60 с до подтверждения: отказ.
4. Устройство без биометрии Strong: понятное сообщение, PIN не принимается.
5. Добавить новый отпечаток: ключ пересоздаётся при следующем запросе, сохранённых данных нет, поэтому ничего не теряется.
